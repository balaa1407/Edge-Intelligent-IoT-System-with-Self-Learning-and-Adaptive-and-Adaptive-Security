# Edge IoT Dashboard — IOT Project

A complete edge IoT monitoring system: ESP32 sensor firmware → MQTT broker → Python bridge → Flask dashboard.

```
┌─────────────────┐        MQTT        ┌──────────────────┐       HTTP      ┌──────────────────┐
│  ESP32 Firmware │ ──────────────────▶│  Bridge (bridge  │ ──────────────▶│  Flask Dashboard │
│  esp32_main.py  │  edgeiot/+/telem.  │     .py)         │  reads log.json│     (app.py)     │
│  (MicroPython)  │                    │  anomaly detect  │                │  templates/      │
└─────────────────┘                    │  risk scoring    │                │  index.html      │
                                       │  writes log.json │                └──────────────────┘
                                       └──────────────────┘
```

## How to Run

### 1 — Install dependencies (PC/server side)
```bash
pip install -r requirements.txt
```

### 2 — Start the MQTT bridge (Terminal 1)
```bash
python bridge.py
```
Connects to `test.mosquitto.org`, subscribes to `edgeiot/#`, processes telemetry,
and writes aggregated records to `log.json`.

### 3 — Start the Flask dashboard (Terminal 2)
```bash
python app.py
```
Open **http://localhost:5000** in your browser.

### 4 — Run the ESP32 firmware - Wokwi Simulator
1. Go to https://wokwi.com/projects/322577683855704658
2. Replace the code with `wokwi_corrected_code.py` from this repo
3. Click "Run" in Wokwi
4. Watch the dashboard update with real-time sensor data!

**Alternative:** Upload `esp32_main.py` to physical ESP32:
```bash
mpremote connect /dev/ttyUSB0 cp esp32_main.py :main.py
```

## Wokwi Simulator for Presentations

**For demonstrations:** Use Wokwi to show real-time data collection and anomaly detection.

### Setup:
1. Go to https://wokwi.com/projects/322577683855704658
2. Replace all code with content from `wokwi_corrected_code.py`
3. Click **"Run"** - simulator will start publishing random sensor readings
4. Watch bridge logs and dashboard update live

### Expected Output:
- **Random temperature:** 20-35°C (different every second)
- **Random humidity:** 30-70% (independent variation)
- **Bridge receives:** `[INFO] [AGG] temp=27.3°C humi=45.2% risk=0/10 mode=NORMAL`
- **Dashboard displays:** Live charts updating every 3 seconds

## MQTT Topic Schema

| Topic | Direction | Payload |
|---|---|---|
| `edgeiot/<device_id>/telemetry` | ESP32 → Broker | JSON with temp, humidity, status, uptime, timestamp |
| `edgeiot/<device_id>/status` | Broker → Bridge (LWT) | `{"status":"OFFLINE","device_id":"..."}` |

### Telemetry Payload Example
```json
{
  "device_id":   "device1",
  "temperature": 25.3,
  "humidity":    54.8,
  "status":      "OK",
  "uptime":      142,
  "timestamp":   1745123456
}
```

## Risk Scoring (bridge.py)

The bridge computes a **1–10 risk score** per device each cycle using multiple factors:

| Factor | Points |
|---|---|
| Temp ≥ 45°C or ≤ 10°C | +5 |
| Temp ≥ 35°C | +2 |
| Humidity ≥ 80% or ≤ 20% | +2 |
| Device-reported `WARNING` status | +2 |
| Temperature Z-score anomaly (> 2σ) | +2 |
| Humidity Z-score anomaly (> 2σ) | +1 |

| Score | Mode |
|---|---|
| 0–3 | NORMAL |
| 4–6 | WARNING |
| 7–10 | CRITICAL |

## Dashboard Features

- **5 stat cards**: avg temperature, avg humidity, risk score (with bar), system mode, online device count
- **Dual-axis chart**: temperature + humidity (left axis) and risk score bars (right axis)
- **Device breakdown panel**: live per-device temp, humidity, risk, and mode
- **Event log**: last 20 records, newest first, with status badges and mode tags
- **Alert banner**: shown when risk ≥ 7 (CRITICAL)
- **Live connection indicator**: turns OFFLINE if Flask can't fetch `/data`
- **Refresh progress bar**: visual countdown to next 3-second refresh

## Configuration

All tunable values are in `CONFIG` dicts at the top of each file — no magic numbers.

**bridge.py CONFIG keys:**
- `anomaly.z_threshold` — standard deviations to flag anomaly (default: 2.0)
- `anomaly.min_history` — readings before detection starts (default: 5)
- `thresholds.*` — absolute temp/humidity alert levels
- `log.interval` — seconds between log writes (default: 3)

**esp32_main.py CONFIG keys:**
- `wifi.ssid / password` — your network credentials
- `devices[]` — list of virtual/real sensor IDs
- `publish_interval` — seconds between MQTT publishes (default: 3)

## Replacing Simulated Sensors

In `esp32_main.py`, swap `read_temperature()` and `read_humidity()` for real sensor calls:

```python
import dht
_sensor = dht.DHT22(machine.Pin(4))

def read_temperature(device_id):
    _sensor.measure()
    return round(_sensor.temperature(), 2)

def read_humidity(device_id):
    _sensor.measure()
    return round(_sensor.humidity(), 2)
```
